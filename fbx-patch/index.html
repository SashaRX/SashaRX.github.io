FBX Patch Tool

A command-line tool for auditing and repairing FBX libraries: materials and textures, UVs and colors, collisions, normals, smoothing, scale, axes and scene cleanup. Process multiple files and folders in one run; no Max, Unity or Qt required.

Workflow: audit an FBX library →

1. Start here

  1. Download and extract the ZIP.
  2. Open PowerShell in the folder containing patch_fbx.exe.
  3. Check the version and available commands:
.\patch_fbx.exe --version
.\patch_fbx.exe --help

This is a console program. Double-clicking the EXE does not open a graphical interface. Examples below use placeholder paths; replace them with your own. Quote paths with spaces. Multiple files and folders, including Unicode paths, are supported.

2. Commands

Repairs are opt-in: a scan without repair flags only reports findings. Start with an audit, then preview the specific changes you need using -n. Applying repairs saves matching FBX files in place.

New in 1.1.1: strict render-channel normalization, missing-smoothing recovery and collision cleanup. Missing UV1 copies authored UV0. The three CTest suites and 262 extracted-package CLI checks pass on generated FBX fixtures. Strict rewrites change FBX object IDs; Unity sub-asset IDs and native Max behavior remain unverified. The 329-file corpus results describe historical 1.0.1 only. Validation details

Ready-made examples · 11 common commands

Audit a model folder

Scan all subfolders, print per-file results and save a Markdown report. No repair flags are enabled, so FBX files stay unchanged.

.\patch_fbx.exe -r -v --report-file audit.md "D:\Models"

Inspect one FBX

Inspect scene, mesh and material data. This mode always leaves FBX files unchanged, even if repair flags are supplied.

.\patch_fbx.exe --inspect "D:\Models\SM_Chair.fbx"

Preview collision and tangent cleanup

Show the proposed repairs without writing FBX files or backups. Remove tangents/binormals and UV/vertex-color data on collision meshes.

.\patch_fbx.exe -n -r --strip-tbn --strip-col-data "D:\Models"

Apply the reviewed cleanup

The same command without -n applies matching repairs in place. Each rewritten FBX gets a .fbx.bak backup by default.

.\patch_fbx.exe -r --strip-tbn --strip-col-data "D:\Models"

Preview material metadata repairs

Enable render-mesh texture shading, fill empty relative texture paths and align diffuse textures with the first UV set. Remove -n after checking the preview to apply.

.\patch_fbx.exe -n --apply-materials-patch "D:\Models\SM_Chair.fbx"

Preview texture lookup

Find missing diffuse textures by material/texture naming conventions, such as M_Chair and T_Chair_Albedo, using the supplied texture folder.

.\patch_fbx.exe -n --guess-textures --texture-root "D:\Textures" "D:\Models\SM_Chair.fbx"

Preview lightmap UV clamping

Clamp UV1, the second UV channel, to [0, 1]. This discards coordinates outside the range; it does not unwrap or pack islands.

.\patch_fbx.exe -n --clamp-uv1 "D:\Models\SM_Chair.fbx"

Preview vertex color repairs

Add missing vertex colors as opaque white and clamp existing RGBA values to [0, 1]. Remove -n after checking the preview to apply.

.\patch_fbx.exe -n --fill-missing-vcolor --clamp-vcolor "D:\Models\SM_Chair.fbx"

Preview conversion to meters

Convert scene units to meters and bake compensating node scales into geometry. Remove -n after checking the preview to apply.

.\patch_fbx.exe -n --convert-to-meters --bake-non-identity-scale "D:\Models\SM_Chair.fbx"

Preview geometry cleanup

Remove unused vertices and degenerate polygons. Remove -n after checking the preview to apply.

.\patch_fbx.exe -n --remove-orphan-vertices --remove-degenerate-polys "D:\Models\SM_Chair.fbx"

Process multiple inputs with four workers

Audit a file and a folder in one run, including subfolders. -j 4 limits parallel processing to four worker processes.

.\patch_fbx.exe -r -j 4 --report-file audit.md "D:\Models\SM_Chair.fbx" "D:\Models\Props"

3. Complete option reference

All 65 user-facing options in version 1.1.1, checked against the downloadable EXE. Every option is described individually; aliases select the same operation. All repairs are off by default.

Strict channel modes 3
OptionWhat it does
--normalize-render-channelsRepairOn render meshes (not _COL, not shared with a _COL node) add each missing UV0/UV1/UV2 on its own layer, filled with (0, 0), (0, 0) and (1, 0); a missing UV1 next to an authored UV0 is an exact copy of UV0 instead, because Unity lightmaps a mesh without TexCoord1 through TexCoord0. Add opaque white colour on layer 0 when no layer has one. Remove UVs on layers ≥ 3, and extra colours when layer 0 holds a valid one. A damaged UV0–UV2 or layer-0 colour is an error: the whole file is left untouched and the run exits 2. Ambiguous layouts are reported and the mesh is skipped. Existing valid channels are never rewritten.
--restore-missing-smoothingRepairOn render meshes with no smoothing element, derive 3ds Max smoothing groups that reproduce the authored normals exactly (1e-5 equality, not an angle) and write them on layer 0. Faceted faces get distinct non-zero groups; only when more than 32 bits would be needed do isolated faceted faces fall back to group 0. A split that groups cannot express, or a mesh with damaged UV0–UV2/colour, is reported and skipped. Normals and tangents are never changed.
--clean-col-geometryRepairOn _COL meshes remove UVs, vertex colours, normals, tangents, binormals, smoothing and material elements, and disconnect the node's materials without destroying them. Geometry, names and transforms are kept. Shared or deformed _COL meshes are reported and skipped.

Internal worker arguments

The dispatcher also accepts three internal worker arguments: --child-mode STATS_PATH (one-file patch worker), --survey-mode STATS_PATH (read-only pool survey worker), and --load-material-pool PATH (load the dispatcher-generated pool). They are implementation protocols, not normal library-processing commands, and are not included in the builder.

Strict modes in detail

Channel names. UV0/UV1/UV2 are FBX layers 0/1/2, which Unity imports as TexCoord0/1/2 (Mesh.uv, Mesh.uv2, Mesh.uv3). The tool's UV2 is not Unity's Mesh.uv2, which is TexCoord1, the tool's UV1.

--normalize-render-channels.

  • Missing UV0 is added as (0, 0); missing UV2 as (1, 0), by-polygon-vertex / index-to-direct. Missing UV1 copies authored UV0 exactly, including mapping, reference mode, values and indices. If UV0 is also missing, the new UV1 uses (0, 0).
  • The added UV is named UVChannel_{k+1} unless the mesh already has a UV set with that name. 3ds Max exports map channels 1 and 3 as UVChannel_1 and UVChannel_3, so an added UV2 then becomes UVChannel_4 (one past the highest existing UVChannel_<n>). Duplicate names would make Max overwrite one channel on re-import. The report's uvnames= shows the names used.
  • A mesh with no colour gets white (1, 1, 1, 1) on layer 0.
  • The main colour is a valid layer-0 colour; colours on other layers are then removed. Colour only on higher layers is ambiguous: the mesh is skipped (CHANNEL-AMBIGUOUS).
  • Diffuse UVs on layers 3 and up are removed.
  • Damaged is not missing, and it is an error. A UV0–UV2 or layer-0 colour element with an unsupported mapping or reference (including legacy eIndex), an empty or short value array, a wrong index count, an out-of-range index or NaN/Inf values is never replaced. It is reported (CHANNEL-DAMAGED) and the whole file is left untouched: no mesh in it is rewritten, no backup is made, an ERROR row is written and the run exits 2. A dry run reports the same error. Values outside [0, 1] are not damage; damage on UV3+ or on a colour that would be removed does not block.
  • A UV gap (e.g. UV0 + UV2 only), a UV in a non-diffuse slot, or UV0–UV2 element order differing from layer order skips the mesh (CHANNEL-AMBIGUOUS, not an error). Only layers 0–2 are compared for element order, since higher UVs are removed.

--restore-missing-smoothing.

  • Runs only when the mesh has no smoothing element and exactly one valid normal element mapped by polygon-vertex or by control point. By control point means all manifold edges are soft.
  • An edge is soft only when both faces carry equal normals at both ends. Equal means 1e-5 per component after normalisation: a float round-trip tolerance, not an angle threshold.
  • The groups are verified against a simulation of Max's smoothing rule. A seam, a hard edge ending inside a smooth region, a non-manifold or inconsistently wound edge, or more than 32 groups gives SMOOTHING-UNREPRESENTABLE and no change. It never falls back to smooth-all or an angle threshold.
  • Regions are greedy-coloured, faceted faces included, so a hard-edged cube gets non-zero groups and is not later detected as missing smoothing. Only if that needs more than 32 bits, isolated faceted faces (a single face whose corner normals no other face shares) get group 0 and use no bit, so a faceted fan or cone with 33+ faces at one apex still succeeds. If every face ends up at 0 the SMOOTHING-RESTORED row carries allzero=1.
  • A mesh with a damaged UV0–UV2 or layer-0 colour is skipped (reason damaged-channels), even without --normalize-render-channels.
  • Contrast with --rebuild-shading:
    • It destroys all normal elements and rebuilds them from smoothing.
    • Or, when there is no smoothing, it derives smoothing by connectivity (dot ≥ 0.9999). That can merge hard edges such as a cylinder seam, and more than 32 islands wrap.
    • Tangents are left stale.
    • Every run rewrites the file.
    • The strict modes therefore never enable it.

--clean-col-geometry.

  • Kept: control points, polygons and their order, edges, hole/visibility elements, user data, names, hierarchy and transforms.
  • Materials are disconnected, never destroyed. A material still used by a render node stays connected there. One left with no user is reported (COL-MATERIALS-ORPHANED).
  • A _COL mesh shared with a render node (COL-SHARED-SKIPPED), with any deformer such as a skin (COL-DEFORMED-SKIPPED), or whose geometry is not a mesh (COL-NOT-MESH-SKIPPED) is skipped.
  • Unity Physics Materials, BallisticMaterial and collider components are out of scope.

Safety.

  • Classification uses the scene as imported. A mesh used by both a render and a _COL node is skipped by every mode (SHARED-MESH-SKIPPED).
  • Render meshes with blend shapes or vertex caches are skipped (RENDER-DEFORMED-SKIPPED); skin-only meshes are processed.
  • Backups:
    • The backup is mandatory, flushed to disk and verified byte for byte before staging.
    • A failed backup leaves the file untouched and exits 2.
    • --no-backup together with a strict flag is rejected (exit 1); legacy runs still accept it.
  • Only FBX 7.1–7.5 and 7.7 are accepted, written back at the same version and encoding. Anything else gives UNSUPPORTED-FBX-VERSION and is skipped.
  • A second run plans nothing and writes nothing, so the .bak is kept.
  • -n previews without writing an FBX, backup or staging file.
  • --inspect stays read-only. Only with a strict flag does it add each mesh's kind and layer slots; plain --inspect output is unchanged.
  • .meta files are never touched.
  • Any mesh error (STRICT-MESH-ERROR) or damaged channel (CHANNEL-DAMAGED) discards the scene before writing.
  • In strict runs neither the per-file lines nor the summary suggest legacy flags.

Rejected combinations. Any strict flag plus any legacy repair flag exits 1 before any file is opened. Examples are --fill-missing-uv1, --strip-col-data, --rebuild-shading, --strip-tbn, --apply-materials-patch, --guess-textures and --convert-to-meters. --no-backup is rejected too. Allowed alongside: --detect-*, --classify-source, --debug-textures, --inspect, -n, -v, -r, -j, --report-file and --short-paths.

4. UV & collisions

Channels are identified by FBX element order, not by their names. --fill-missing-uv1 and --fill-missing-uv2 add constant (1, 1) values; they do not generate a lightmap unwrap. --uv2-y-zero changes synthesized UV2 values to (1, 0).

Collision cleanup recognizes _COL, _Collider and _Collision suffixes without case sensitivity, including numeric tails such as _Collider_26. --strip-col-data removes UV and vertex-color layers from collision meshes while preserving data shared with render meshes.

5. Backups

By default, each successful rewrite creates <file>.fbx.bak, for example SM_Chair.fbx.bak. A later rewrite refreshes this backup. Audits, dry runs and repairs that have nothing to change leave the FBX and its backup untouched.

To undo a repair, copy the backup over the FBX or restore it under a new .fbx name. --no-backup disables backup creation. Clamping and cleanup can discard data; inspect the preview before applying them.

Saving through the FBX SDK is not byte-identical to the input. This utility works with FBX; it does not produce GLB or meshopt output.

Strict modes always require a flushed, byte-verified backup and reject --no-backup or legacy repair flags. Preview with -n before applying. Their UV numbering follows FBX layers; UV1 is Unity Mesh.uv2.
