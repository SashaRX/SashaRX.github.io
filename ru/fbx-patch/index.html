FBX Patch Tool

Консольный инструмент для проверки и исправления целых библиотек FBX: материалы и текстуры, UV и цвета, коллизии, нормали, сглаживание, масштаб, оси и очистка сцены. Обрабатывает несколько файлов и папок за один запуск; Max, Unity и Qt не нужны.

Сценарий: аудит библиотеки FBX →

1. Начало работы

  1. Скачай и распакуй ZIP.
  2. Открой PowerShell в папке с patch_fbx.exe.
  3. Проверь версию и доступные команды:
.\patch_fbx.exe --version
.\patch_fbx.exe --help

Это консольная программа. Двойной клик по EXE не открывает графический интерфейс. В примерах указаны условные пути — замени их своими. Пути с пробелами заключай в кавычки. Можно передавать несколько файлов и папок, в том числе с кириллицей в путях.

2. Команды

Исправления включаются явно: без флагов исправлений программа только сообщает о найденных проблемах. Начни с аудита, затем проверь нужные изменения с помощью -n. При применении соответствующие FBX перезаписываются на месте.

Новое в 1.1.1: строгая нормализация render-каналов, восстановление отсутствующего сглаживания и очистка коллизий. Отсутствующий UV1 копирует авторский UV0. Пройдены 3 набора CTest и 262 CLI-проверки распакованного ZIP на сгенерированных FBX. Строгая перезапись меняет ID объектов FBX; fileID Unity и нативная работа Max не проверены. Результаты на 329 рабочих файлах относятся только к прежней версии 1.0.1. Подробности проверки

Готовые примеры · 11 типовых команд

Проверить папку моделей

Проверка всех вложенных папок, вывод результатов по файлам и отчёт Markdown. Флаги исправлений не включены, поэтому FBX остаются без изменений.

.\patch_fbx.exe -r -v --report-file audit.md "D:\Models"

Посмотреть содержимое одного FBX

Просмотр данных сцены, мешей и материалов. Этот режим всегда оставляет FBX без изменений, даже если переданы флаги исправлений.

.\patch_fbx.exe --inspect "D:\Models\SM_Chair.fbx"

Предпросмотр очистки коллизий и тангенсов

Показать планируемые исправления без записи FBX и резервных копий: удалить тангенсы/бинормали и UV/цвета вершин у мешей коллизий.

.\patch_fbx.exe -n -r --strip-tbn --strip-col-data "D:\Models"

Применить проверенную очистку

Та же команда без -n применяет найденные исправления в исходных файлах. Для каждого перезаписанного FBX по умолчанию создаётся копия .fbx.bak.

.\patch_fbx.exe -r --strip-tbn --strip-col-data "D:\Models"

Предпросмотр исправлений данных материалов

Включить отображение текстур, заполнить пустые относительные пути текстур и привязать diffuse-текстуры к первому UV-каналу. Для применения убери -n после проверки.

.\patch_fbx.exe -n --apply-materials-patch "D:\Models\SM_Chair.fbx"

Предпросмотр поиска текстур

Найти недостающие diffuse-текстуры по соглашению имён материалов и текстур, например M_Chair и T_Chair_Albedo, в указанной папке текстур.

.\patch_fbx.exe -n --guess-textures --texture-root "D:\Textures" "D:\Models\SM_Chair.fbx"

Предпросмотр ограничения lightmap UV

Ограничить UV1, второй UV-канал, диапазоном [0, 1]. Координаты за пределами диапазона теряются; команда не создаёт развёртку и не упаковывает острова.

.\patch_fbx.exe -n --clamp-uv1 "D:\Models\SM_Chair.fbx"

Предпросмотр исправлений цветов вершин

Заполнить отсутствующие цвета вершин непрозрачным белым и ограничить существующие RGBA диапазоном [0, 1]. Для применения убери -n после проверки.

.\patch_fbx.exe -n --fill-missing-vcolor --clamp-vcolor "D:\Models\SM_Chair.fbx"

Предпросмотр перевода в метры

Перевести единицы сцены в метры и запечь компенсирующий масштаб узлов в геометрию. Для применения убери -n после проверки.

.\patch_fbx.exe -n --convert-to-meters --bake-non-identity-scale "D:\Models\SM_Chair.fbx"

Предпросмотр очистки геометрии

Удалить неиспользуемые вершины и вырожденные полигоны. Для применения убери -n после проверки.

.\patch_fbx.exe -n --remove-orphan-vertices --remove-degenerate-polys "D:\Models\SM_Chair.fbx"

Обработать несколько путей четырьмя процессами

Проверить файл и папку за один запуск, включая вложенные папки. -j 4 ограничивает параллельную обработку четырьмя рабочими процессами.

.\patch_fbx.exe -r -j 4 --report-file audit.md "D:\Models\SM_Chair.fbx" "D:\Models\Props"

3. Все параметры

62 пользовательских параметра версии 1.1.1, сверенные со скачиваемым EXE. Каждый описан отдельно; алиасы запускают ту же операцию. Все исправления по умолчанию выключены.

Строгие режимы каналов 3
ПараметрДействие
--normalize-render-channelsИсправлениеДля render-мешей (не _COL и без общей геометрии с _COL) добавить каждый отсутствующий UV0/UV1/UV2 в собственный слой со значениями (0, 0), (0, 0) и (1, 0). Отсутствующий UV1 при авторском UV0 — точная копия UV0: Unity использует TexCoord0 для лайтмапы меша без TexCoord1, и копия сохраняет это поведение. Если цвета нет ни в одном слое, добавить в слой 0 белый непрозрачный цвет. Удалить UV в слоях от 3 и выше, а лишние цвета — если в слое 0 есть корректный. Повреждённый UV0–UV2 или цвет слоя 0 считается ошибкой: весь файл остаётся нетронутым, код выхода 2. Неоднозначные каналы попадают в отчёт, меш пропускается. Существующие корректные каналы не переписываются.
--restore-missing-smoothingИсправлениеДля render-мешей без элемента сглаживания вычислить группы сглаживания 3ds Max, которые в точности воспроизводят записанные нормали (равенство с допуском 1e-5, а не угол), и записать их в слой 0. Гранёные грани получают разные ненулевые группы; только если нужно больше 32 бит, изолированные гранёные грани получают группу 0. Если разбиение группами не выражается или у меша повреждены UV0–UV2 или цвет, меш попадает в отчёт и пропускается. Нормали и тангенты не меняются.
--clean-col-geometryИсправлениеУ _COL-мешей удалить UV, вершинные цвета, нормали, тангенты, бинормали, сглаживание и элементы материалов, а материалы узла отсоединить, не удаляя их. Геометрия, имена и трансформации сохраняются. Общие с render-узлом и деформируемые _COL-меши попадают в отчёт и пропускаются.

Строгие режимы подробно

Имена каналов. UV0/UV1/UV2 — это слои FBX 0/1/2. Unity импортирует их как TexCoord0/1/2, то есть Mesh.uv, Mesh.uv2 и Mesh.uv3. UV2 этой программы — не Mesh.uv2 в Unity: тот соответствует TexCoord1, то есть UV1 программы.

--normalize-render-channels.

  • Отсутствующий UV0 получает (0, 0), UV2 — (1, 0), по вершинам полигонов с index-to-direct. Отсутствующий UV1 точно копирует существующий UV0: mapping, reference, значения и индексы. Если UV0 тоже отсутствовал, новый UV1 получает (0, 0).
  • Добавленный UV называется UVChannel_{k+1}, если такого имени у меша ещё нет. 3ds Max экспортирует каналы карт по номерам: меш с каналами 1 и 3 приходит с UVChannel_1 и UVChannel_3 в слоях 0 и 1. Тогда добавленный UV2 получает имя UVChannel_4 — на единицу больше наибольшего номера UVChannel_<n>. С двумя одинаковыми именами Max при повторном импорте затёр бы один канал другим. Использованные имена видны в поле отчёта uvnames=.
  • Меш без цвета получает белый (1, 1, 1, 1) в слое 0.
  • Основной цвет — корректный цвет слоя 0; цвета других слоёв тогда удаляются. Если цвет есть только в верхних слоях, выбор неоднозначен: меш пропускается (CHANNEL-AMBIGUOUS).
  • Diffuse-UV в слоях 3 и выше удаляются.
  • Повреждённый канал — не отсутствующий, и это ошибка. Элемент UV0–UV2 или цвета слоя 0 с неподдерживаемым mapping или reference (включая устаревший eIndex), пустым или коротким массивом значений, неверным числом индексов, индексом вне диапазона или значениями NaN/Inf никогда не заменяется заполнением. Он попадает в отчёт (CHANNEL-DAMAGED), а весь файл остаётся нетронутым: ни один меш в нём не переписывается, резервная копия не создаётся, в отчёт пишется строка ERROR, код выхода 2. Пробный запуск (-n) сообщает ту же ошибку. Значения вне [0, 1] повреждением не считаются. Повреждение UV3 и выше или цвета, который всё равно удаляется, запись не блокирует.
  • Меш пропускается без ошибки (CHANNEL-AMBIGUOUS), если в UV есть разрыв (например, только UV0 и UV2), UV лежит в недиффузном слоте или порядок элементов UV0–UV2 не совпадает с порядком слоёв. Порядок сравнивается только для слоёв 0–2: UV выше всё равно удаляются.

--restore-missing-smoothing.

  • Работает, только если у меша нет элемента сглаживания и есть ровно один корректный элемент нормалей с mapping по вершинам полигонов или по контрольным точкам. При нормалях по контрольным точкам все манифолдные рёбра мягкие.
  • Ребро мягкое, только если у обеих граней на обоих его концах одинаковые нормали. «Одинаковые» — это разница не больше 1e-5 по каждой компоненте после нормализации: допуск на округление float, а не порог угла.
  • Группы проверяются симуляцией правила сглаживания Max. Шов, жёсткое ребро, обрывающееся внутри гладкой области, неманифолдное ребро, несогласованный порядок обхода или потребность больше чем в 32 группах дают SMOOTHING-UNREPRESENTABLE, и меш не меняется. Сглаживание «всё мягкое» и порог угла не применяются никогда.
  • Регионы раскрашиваются жадно, включая гранёные грани, поэтому куб с жёсткими рёбрами получает ненулевые группы и --detect-missing-smoothing не примет результат за отсутствие сглаживания. Только если нужно больше 32 бит, изолированные гранёные грани (отдельная грань, нормали которой в углах не совпадают ни с одной соседней) получают группу 0 и не занимают бит, так что гранёный веер или конус с 33 и более гранями у одной вершины всё равно обрабатывается. Если все грани получили 0, строка SMOOTHING-RESTORED содержит allzero=1.
  • Меш с повреждённым UV0–UV2 или цветом слоя 0 пропускается (причина damaged-channels), даже если --normalize-render-channels не задан.
  • Чем это отличается от --rebuild-shading:
    • --rebuild-shading удаляет все элементы нормалей и пересчитывает их по сглаживанию.
    • Если сглаживания нет, он выводит его по связности почти равных нормалей (dot ≥ 0.9999). Так может слиться жёсткое ребро вроде шва цилиндра, а при больше чем 32 островах группы повторяются.
    • Тангенты остаются устаревшими.
    • Каждый запуск перезаписывает файл.
    • Поэтому строгие режимы его никогда не включают.

--clean-col-geometry.

  • Сохраняются контрольные точки, полигоны и их порядок, рёбра, элементы hole/visibility, пользовательские данные, имена, иерархия и трансформации.
  • Материалы отсоединяются, но не удаляются. Материал, который использует render-узел, остаётся подключённым к нему. Материал, оставшийся без пользователей, попадает в отчёт (COL-MATERIALS-ORPHANED).
  • Пропускаются _COL-меши, общие с render-узлом (COL-SHARED-SKIPPED), меши с любым деформером, например со скином (COL-DEFORMED-SKIPPED), и _COL-узлы, чья геометрия не меш (COL-NOT-MESH-SKIPPED).
  • Physics Material, BallisticMaterial и компоненты коллайдеров Unity вне области действия программы.

Безопасность.

  • Классификация выполняется по сцене в том виде, в каком она импортирована. Меш, который используют и render-, и _COL-узел, пропускается всеми режимами (SHARED-MESH-SKIPPED).
  • Render-меши с blend shapes или vertex cache пропускаются (RENDER-DEFORMED-SKIPPED); меши только со скином обрабатываются.
  • Резервная копия:
    • Копия обязательна: до записи она сбрасывается на диск и сверяется побайтно.
    • Если её не удалось создать, файл не меняется, а код выхода равен 2.
    • --no-backup вместе со строгим флагом запрещён (код выхода 1); в обычных запусках он по-прежнему работает.
  • Принимаются только FBX 7.1–7.5 и 7.7; файл записывается в той же версии и кодировке. Остальное получает UNSUPPORTED-FBX-VERSION и пропускается.
  • Повторный запуск ничего не планирует и ничего не пишет, .bak сохраняется.
  • -n показывает план без записи FBX, резервной копии и промежуточных файлов.
  • --inspect остаётся только чтением. Тип каждого меша и его слои он показывает, только если указан и строгий флаг; вывод обычного --inspect не меняется.
  • Файлы .meta не затрагиваются.
  • Ошибка на любом меше (STRICT-MESH-ERROR) или повреждённый канал (CHANNEL-DAMAGED) отменяет запись всей сцены.
  • В строгих запусках ни строки по файлам, ни итоговая сводка не предлагают устаревшие флаги.

Запрещённые сочетания. Любой строгий флаг вместе с любым устаревшим флагом исправления завершает работу с кодом 1 ещё до открытия файлов. Примеры: --fill-missing-uv1, --strip-col-data, --rebuild-shading, --strip-tbn, --apply-materials-patch, --guess-textures, --convert-to-meters. --no-backup тоже запрещён. Разрешены вместе с ними: --detect-*, --classify-source, --debug-textures, --inspect, -n, -v, -r, -j, --report-file, --short-paths.

Строки отчёта. Каждая строка содержит node='…' mesh='…' kind=render|col|shared.

Состав вида uv,col|uv|uv перечисляет слои по порядку. ! означает повреждение, * — UV в другом слоте, ~order — расхождение порядка.

.\patch_fbx.exe -n -r -v --report-file strict.txt --normalize-render-channels --restore-missing-smoothing --clean-col-geometry "D:\Models"
.\patch_fbx.exe -r --normalize-render-channels "D:\Models"
.\patch_fbx.exe -r --restore-missing-smoothing "D:\Models"
.\patch_fbx.exe -r --clean-col-geometry --report-file col.md "D:\Models"

Проверка релиза в Windows: MSVC 19.44 / FBX SDK 2020.3.9: пройдены все 3 набора CTest и 262 CLI-проверки распакованного ZIP на сгенерированных FBX. Строгая перезапись меняет UniqueID объектов FBX (34 из 34 в тесте); стабильность ID не гарантируется. Тест длинного пути пройден; файл FBX 6.x для проверки отказа создан вручную.

Не проверены: импорт/TexCoord в Unity, стабильность fileID вложенных ассетов, сглаживание внутри 3ds Max и все поддерживаемые версии FBX. Результаты на тестовых файлах не подтверждают совместимость рабочих ассетов. Mesh Compression в Unity может переквантовать UV после добавления канала; сглаживание влияет на Normals=Calculate, а не на импортированные авторские нормали.

Каналы определяются по порядку элементов FBX, а не по именам. --fill-missing-uv1 и --fill-missing-uv2 добавляют постоянные значения (1, 1), а не создают lightmap-развёртку. --uv2-y-zero меняет значения добавляемого UV2 на (1, 0).

Очистка коллизий распознаёт суффиксы _COL, _Collider и _Collision без учёта регистра, в том числе с числовым хвостом вроде _Collider_26. --strip-col-data удаляет UV и цвета вершин у коллизий, сохраняя данные, общие с render-мешами.

5. Резервные копии

По умолчанию при каждой успешной перезаписи создаётся <файл>.fbx.bak, например SM_Chair.fbx.bak. Следующая перезапись обновляет эту копию. Аудит, предпросмотр и исправления без фактических изменений не трогают FBX и его резервную копию.

Для отмены исправления скопируй резервную копию поверх FBX или восстанови её под новым именем с расширением .fbx. Флаг --no-backup отключает создание копий. Ограничение диапазонов и очистка могут удалять данные — проверяй предпросмотр перед применением.

Сохранение через FBX SDK не сохраняет побайтовое совпадение с исходным файлом. Утилита работает с FBX; вывод GLB и meshopt в ней отсутствует.

Строгие режимы всегда требуют записанную и побайтно проверенную копию. --no-backup и прежние исправления с ними запрещены. Сначала проверь -n. UV нумеруются по слоям FBX; UV1 соответствует Unity Mesh.uv2.
