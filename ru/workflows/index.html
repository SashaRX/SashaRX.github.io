Практические сценарии

Выбери задачу, выполни шаги и проверь результат. Сценарии дополняют полные инструкции, не повторяя каждую настройку.

Подходящих задач нет. Попробуй другой запрос или сбрось фильтры.

Экспортировать сцену в отдельные файлы моделейОдин Dummy → один FBX. Выбери модели для этой партии.MAX ModelBatch

Для каждой модели нужна своя иерархия Dummy. В 1.3.6 выдели меши одной модели и открой Export → Models. Введи Asset name, переключи At center / At bottom / At LOD0 pivot, при необходимости включи Auto LODs и нажми Create Dummy; повтори для остальных. См. компактные элементы Dummy.

  1. При создании корня задай понятное Asset name и позицию в центре или у пола. Для обычных частей составной модели отключи LOD-именование по полигонам: оно предназначено для альтернативных уровней детализации.
  2. Укажи общую Project folder. Сними выделение объектов в Max и нажми Analyze, чтобы собрать Dummy сцены. При наличии выделения Analyze собирает корни выбранных объектов.
  3. В Models выбери All models или нужные теги и отметь корни для экспорта. All / None / Invert работают только с моделями, видимыми по фильтру.
  4. Проверь Destination, Export settings и Mesh channels. Нажми Export FBX и прочитай статус или Log.

Проверь результат. Каждый отмеченный корень, видимый по фильтру тегов, станет отдельным FBX со своей иерархией и _COL. Выделение строки в Max и галочка экспорта — разные действия.

Разложить props и другие модели по папкам проектаХрани относительные маршруты в Dummy и экспортируй несколько тегов вместе.MAX ModelBatch

Используй общий корень проекта, например D:\Game\Assets, и отдельный тег для каждого маршрута.

  1. Задай Project folder, открой Export Tags → Add tag и введи ключ, например props.
  2. Нажми Browse... возле Relative folder и выбери папку внутри проекта. Для D:\Game\Assets\Models\Props сохранится Models/Props. Выбери цвет.
  3. Назначь тег в последнем столбце Export → Models. Для нескольких корней выдели строки и используй правый клик → Assign export tag to selected roots.
  4. Проверь итоговый Destination. В Tag filter выбери один или несколько тегов, отметь видимые корни и сохрани .max, чтобы сохранить фильтр и галочки экспорта.

Проверь результат. SM_Chair с тегом props экспортируется в D:\Game\Assets\Models\Props\SM_Chair.fbx. Dummy хранит тег, относительный маршрут и цвет; в другом проекте абсолютный корень задаётся отдельно.

Если корень проекта уже Assets, не добавляй Assets в относительный путь ещё раз. Отсутствующее определение тега или два корня с одним итоговым файлом блокируют экспорт до исправления.

Сравнить швы текстурной и lightmap-развёрткиПроверяй UV0 / UV1 при редактировании, с depth test и удобным интервалом обновления.MAX ModelBatch

Выдели нужные меши. Оверлей читает итоговый стек модификаторов, включая Editable Poly и Unwrap UVW.

  1. Открой Viewport → UV seams, включи Show UV seams и выбери Selected objects для проверки выбранных мешей.
  2. Выбери UV1 (Max channel 2) для lightmap-швов или Both (compare) для сравнения с UV0 / Max channel 1.
  3. В режиме Both опция Only differences скрывает общие швы. Настрой читаемые цвета и включи Hide occluded seams (Depth test), чтобы скрыть линии за поверхностями.
  4. Если редактирование тяжёлое, попробуй Refresh interval 200–500 мс. При необходимости нажми Refresh; Details покажет пропущенные узлы и проблемы UV.

Проверь результат. Оверлей продолжает работать при смене вкладки и закрытии панели. Он показывает границы швов; создание, упаковку и проверку корректности lightmap-развёртки нужно выполнять отдельно.

Посмотреть один LOD и организовать слои сценыПереключай уровни детализации и создавай общие слои LOD / COL.MAX ModelBatch

Используй имена объектов или групп: Chair_LOD0, Chair_LOD1 и Chair_COL.

  1. Открой Viewport → LOD preview и выбери обнаруженный уровень. Previous / Next пропускают отсутствующие уровни.
  2. Отключи Show objects without LOD names, чтобы убрать посторонние объекты. Дети наследуют ближайшего предка с LOD-именем, если у них нет своего явного маркера.
  3. Выбери All LODs, чтобы восстановить обычную видимость перед дальнейшей работой со сценой.
  4. Для постоянных общих слоёв используй Export → Models → Scene tools → Organize export layers. Кнопка создаёт недостающие слои и обрабатывает всю сцену, независимо от выделения и фильтров экспорта.

Проверь результат. LOD-просмотр фильтрует вьюпорт, но не определяет состав экспорта. Организация слоёв меняет принадлежность объектов, сохраняет настройки слоёв и отменяется одним Ctrl+Z.

Импортировать папку FBX в одну сценуВыбери несколько файлов, настрой партию и восстанови маршруты из метаданных.MAX ModelBatch

Все выбранные файлы импортируются в текущую сцену Max. Абсолютную Project folder для принимающего проекта задай отдельно.

  1. Открой FBX Import → Folder → Browse.... Если содержимое папки изменилось, нажми Refresh.
  2. Выдели файлы через Ctrl/Shift или используй Select All.
  3. Включи Show FBX options for the first file, если нужны настройки штатного импортера Max. Для файлов этого плагина оставь Restore export tags and relative folders from FBX включённым.
  4. Нажми Import Selected, затем проверь Status каждого файла и отчёт. Stop after current file завершит текущий файл перед остановкой партии.

Проверь результат. Выбранные FBX попадают в сцену. При наличии метаданных плагина восстанавливаются теги и относительные маршруты; конфликтующие маршруты получают отдельные теги. Отдельный .max для каждого FBX не создаётся.

Проверить библиотеку FBX и получить общий отчётСканирование вложенных папок без изменения моделей. Max не требуется.FBX Patch Tool

Распакуй FBX Patch Tool 1.0.1 и открой PowerShell рядом с patch_fbx.exe. Замени пример папки ниже своей.

  1. Проверь программу командой .\patch_fbx.exe --version.
  2. Запусти аудит ниже: -r включает вложенные папки, -v показывает результаты по файлам, -j 4 ограничивает обработку четырьмя процессами.
  3. Открой audit.md в текущей папке и проверь найденные модели. Существующий отчёт с таким именем будет перезаписан.
  4. Для подробных данных мешей и материалов одного файла выбери --inspect в конструкторе команд. Проверяй код завершения вместе с отчётом: найденные проблемы сами по себе не исключают код 0.
.\patch_fbx.exe -r -v -j 4 --report-file 'audit.md' 'D:\Models'

Проверь результат. Флаги исправлений не включены, поэтому исходные FBX и резервные копии не меняются. Код 2 означает сбой импорта или обработки хотя бы одного файла; код 1 — неверные аргументы или отсутствие подходящих файлов.

Посмотреть план очистки коллизий и тангенсовПроверь предлагаемые изменения, сохранив исходные FBX без записи.FBX Patch Tool

Используй после аудита, когда нужно согласовать одинаковую очистку для всей папки.

  1. Запусти команду ниже со своей папкой моделей. Оставь -n: это режим dry-run.
  2. Проверь план удаления тангенсов/бинормалей и очистки UV/цветов вершин у мешей коллизий.
  3. Для других операций выбери Предпросмотр в конструкторе команд. Например, ограничение UV меняет координаты вне диапазона, но не создаёт и не упаковывает lightmap-развёртку.
  4. После проверки предпросмотра убери -n, чтобы применить выбранные исправления. В 1.0.1 ошибка временного экспорта исправлена; по умолчанию создаётся .fbx.bak.
.\patch_fbx.exe -n -r --strip-tbn --strip-col-data 'D:\Models'

Проверь результат. Команда показывает план без записи FBX и резервных копий. Убирай -n после проверки выбранных исправлений и входных путей.

В 1.0.1 два набора исправлений проверены на 329 копиях рабочих файлов, включая точные резервные копии и повторное применение. Конфликтующие общие UV0-привязки отмечаются как UVSET-CONFLICT и сохраняются.

Версии и иллюстрации

MAX ModelBatch 1.3.6 и FBX Patch Tool 1.0.1. Используются существующие тестовые снимки Max 2024 из версии 1.2.0, поэтому на них встречаются старые названия. В иллюстрированном руководстве показаны нативные заголовки и новая компактная компоновка. Готовые пакеты и SHA-256 доступны публично.
