Export a scene as separate model filesOne Dummy root → one FBX. Choose the assets that belong in this batch.MAX ModelBatch

Start with one Dummy hierarchy per asset. In 1.3.9, select one asset’s meshes and open Export → Models. Enter Asset name, toggle At center / At bottom / At LOD0 pivot, optionally enable Auto LODs and click Create Dummy; repeat for the other assets. See the compact Dummy controls.

  1. Choose an explicit Asset name and a center or floor pivot when creating a root. Leave polygon-count LOD naming off for ordinary parts of a multipart model; it is intended for alternative detail levels.
  2. Set the common Project folder. Clear Max’s object selection and click Analyze to collect scene Dummies. With a selection, Analyze collects its Dummy roots instead.
  3. In Models, choose All models or the required subpaths, then check the roots to export. All / None / Invert affect only roots shown by the current filter.
  4. Check Destination, Export settings and Mesh channels. Click Export FBX and read the status or Log.

Check the result. Every checked root visible through the current subpath filter becomes its own FBX, including its hierarchy and _COL meshes. Selecting a row in Max is separate from checking it for export.

Send props and other models to project foldersStore relative routes on Dummies and export several subpaths together.MAX ModelBatch

Use a common project root, such as D:\Game\Assets, and a subpath for each output route.

  1. Set Project folder, then open SubPath / Tags → Add subpath and enter a key such as props.
  2. Use Browse... beside Relative folder to choose a folder inside the project. Selecting D:\Game\Assets\Models\Props stores Models/Props. Choose a color.
  3. Assign the subpath in the last column of Export → Models. For several roots, select their rows and use right-click → Assign export subpath to selected roots.
  4. Check the final Destination. Use SubPath filter to show one or several subpaths, mark the visible roots and save the .max scene to retain the filter and export checkboxes.

Check the result. SM_Chair with subpath props exports to D:\Game\Assets\Models\Props\SM_Chair.fbx. The Dummy retains its subpath, relative route and color; a receiving project sets its own absolute root.

If the project root is already Assets, do not repeat Assets in the relative route. Missing subpath definitions or two roots targeting the same file block export until corrected.

Compare texture and lightmap UV seamsInspect UV0 / UV1 while editing, with depth testing and a suitable refresh interval.MAX ModelBatch

Select the meshes you want to inspect. The overlay reads the evaluated modifier stack, including Editable Poly and Unwrap UVW.

  1. Open Viewport → UV seams, enable Show UV seams and choose Selected objects for focused inspection.
  2. Choose UV1 (Max channel 2) for lightmap seams, or Both (compare) to compare them against UV0 / Max channel 1.
  3. In Both mode, Only differences hides shared seams. Set readable colors and enable Hide occluded seams (Depth test) to hide lines behind surfaces.
  4. If editing feels heavy, try a Refresh interval of 200–500 ms. Click Refresh when needed and use Details for skipped nodes or missing UV data.

Check the result. The overlay stays active when you switch tabs or close the panel. It displays seam boundaries; it does not generate, pack or validate a lightmap unwrap.

Inspect one LOD and organize scene layersPreview detail levels separately, then create shared LOD / COL layers.MAX ModelBatch

Use object or group names such as Chair_LOD0, Chair_LOD1 and Chair_COL.

  1. Open Viewport → LOD preview and choose a detected level. Previous / Next skip absent levels.
  2. Turn off Show objects without LOD names when you want a focused view. Children inherit the closest named LOD ancestor unless they have their own explicit marker.
  3. Choose All LODs to restore normal visibility before continuing scene work.
  4. Use Export → Models → Scene tools → Organize export layers when you want permanent shared layers. The action creates missing layers and processes the whole scene, independently of selection and export filters.

Check the result. LOD preview filters the viewport; it does not decide which nodes are exported. Layer organization changes membership, keeps layer settings and can be undone with one Ctrl+Z.

Import a folder of FBX files into one sceneSelect several files, configure the batch and restore routing metadata.MAX ModelBatch

All selected files are imported into the current Max scene. Set the receiving project’s absolute Project folder separately.

  1. Open FBX Import → Folder → Browse.... Click Refresh if the directory changed.
  2. Select the required files with Ctrl/Shift or use Select All.
  3. Enable Show FBX options for the first file when you need Max’s native import settings. Keep Restore export subpaths and relative folders from FBX enabled for files exported by this plugin.
  4. Click Import Selected, then review each file’s Status and the report. Stop after current file finishes the ongoing file before ending the batch.

Check the result. The scene receives the selected FBX files. Plugin metadata restores relative routes and subpaths when present; conflicting routes become separate subpaths. The batch does not create a .max file per input.

Audit an FBX library and get one reportScan subfolders without modifying models. No Max installation required.FBX Patch Tool

Extract FBX Patch Tool 1.0.1 and open PowerShell beside patch_fbx.exe. Replace the example folder below with your own.

  1. Check the executable with .\patch_fbx.exe --version.
  2. Run the audit command below: -r includes subfolders, -v prints per-file results and -j 4 limits processing to four workers.
  3. Read audit.md in the current directory and inspect the reported models. An existing report with that name will be overwritten.
  4. For detailed mesh and material data in one file, use --inspect in the command builder. Check the process return code as well as the report: findings alone can still return 0.
.\patch_fbx.exe -r -v -j 4 --report-file 'audit.md' 'D:\Models'

Check the result. No repair flags are enabled, so FBX inputs and backups remain unchanged. Return code 2 means at least one file could not be imported or processed; code 1 means invalid arguments or no eligible inputs.

Preview collision and tangent cleanupSee the proposed changes while keeping the source FBX files untouched.FBX Patch Tool

Use this after an audit, when you want to review a consistent cleanup across a folder.

  1. Run the command below with your model folder. Keep -n: it selects dry-run.
  2. Review proposed tangent/binormal removal and UV/vertex-color cleanup on collision meshes.
  3. In the command builder, choose Preview to combine other operations. For example, UV clamping changes out-of-range coordinates; it does not unwrap or pack lightmaps.
  4. After reviewing the preview, remove -n to apply the selected repairs. Version 1.0.1 fixes the staged-export failure and keeps .fbx.bak backups by default.
.\patch_fbx.exe -n -r --strip-tbn --strip-col-data 'D:\Models'

Check the result. The command previews changes without writing FBX files or backups. Remove -n only after checking the selected repairs and input paths.

1.0.1 verified two repair sets on 329 copied production files, including exact backups and repeat runs. Conflicting shared UV0 bindings are reported as UVSET-CONFLICT and preserved.
